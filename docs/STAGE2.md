# Второй этап: проверка области и проект заключения

## Запуск

Python 3.12. Из корня проекта:

```bash
source .venv/bin/activate
pip install -r requirements.txt
python app.py
```

Открыть http://127.0.0.1:7860. Первый экран: «Снимок и заключение».
Пакетный анализ первого этапа сохранён во второй вкладке.

1. Выберите JPG/PNG или демо-пример и выполните анализ.
2. Сравните зелёную согласованную область внимания и оранжевую нестабильную область с исходным снимком.
3. Откройте вкладку «Правка F1». Исправьте выделение кистью или ластиком. Можно стереть область полностью.
4. Нажмите «Обновить текст по области F1». Кнопка пересоздаёт текст по новой маске, предыдущий текст остаётся в истории.
5. Отредактируйте проект заключения. При необходимости укажите проверяющего и отметьте проверку. Это техническая отметка, не электронная подпись и не проверка квалификации.
6. Сохраните и скачайте PDF или полный ZIP. Повторное сохранение создаёт новую папку, не перезаписывает предыдущую.

Если маска изменилась после последнего применения, сохранение блокируется до обновления черновика. Правка текста или маски снимает отметку проверки и скрывает старые ссылки скачивания. Свободный текст врача не проходит медицинскую проверку алгоритмом.

## Что реализовано

- Grad-CAM по 5 вариантам: исходный снимок, сдвиги ±3 пикселя по горизонтали, сдвиги ±3 по вертикали вместе с яркостью 0.92/1.08. Карты возвращаются в исходные координаты.
- Голосование карт по порогам 0.4, 0.5, 0.6. Согласованная область - крупнейшая компонента с долей голосов от 0.6; нестабильная - доля между 0 и 0.8. Цвета могут перекрываться: зелёный означает консенсус, оранжевый показывает чувствительность за его пределами.
- Врач видит полноразмерный исходный снимок. Удаляются letterbox-поля, маска переносится обратно с учётом округления масштаба.
- Уверенность классификатора, порог 70%, стабильность класса на 5 вариантах, предупреждение при ограниченном качестве.
- Находка F1, координаты, площадь и рамка в пикселях; расположение только на изображении, без утверждения анатомической стороны.
- Редактирование текста и маски. Сохранение исходного и итогового выделения, автоматического черновика, итогового текста и истории изменения области.
- PDF с кириллицей, автономный HTML, TXT, JSON, PNG-маски и полный ZIP.

Сохранения находятся в `.review_exports/`, исключены из Git. Можно задать `MRI_REVIEW_DIR`. Данные обрабатываются локально; приложение по умолчанию слушает только 127.0.0.1. Контроль доступа, шифрование хранилища, DICOM-обезличивание и клиническое внедрение в прототипе не реализованы.

## Проверка

```bash
python -m unittest discover -s tests -v
python -m src.evaluate_stage2 --n 40
```

Результаты - `reports/stage2/comparison.json`. Сравнение: все 17 ошибок исходного теста и 23 дополнительных снимка, seed 2050. Это намеренно обогащённая ошибками выборка, не оценка общей accuracy.

- Исходный классификатор не менялся: сохранённые результаты на 1100 снимках - accuracy 98.45%, macro-F1 98.42%.
- Порог 70%: 31 снимок, 13 из 17 ошибок отмечены, 4 ошибки не отмечены.
- На сравнительных 40 снимках добавление нестабильности класса не увеличило число отмеченных ошибок: 13 из 17 до и после.
- В 40 из 40 автоматически созданных текстов наличие области и площадь совпадают с маской. Свободный текст после правки врача требует ручной проверки.
- Медиана времени анализа второго этапа на этой машине - около 2.47 с. Это 5 карт Grad-CAM, а не замер прежнего однопроходного режима.
- В UI вручную проверены: анализ, ластик, применение новой области, изменение площади в тексте, правка текста, сохранение PDF/ZIP, блокировка экспорта при неприменённой маске.

## Ограничения, которые нельзя выдавать за выполненные

**Улучшение точности границ опухоли не доказано.** Масок врачебной разметки нет, Dice и IoU не рассчитаны. Консенсус и его нестабильность характеризуют поведение классификатора, а не вероятность наличия опухоли в пикселе. Grad-CAM не заменяет сегментацию. Для полного подтверждения пункта 3.1 нужны маски врача и независимое сравнение первого и второго методов на одних и тех же размеченных снимках.

Не определяются глиобластома как подтип, ядро и отёк. Из одного JPG нельзя получить достоверные миллиметры, объём, анатомическую сторону, тип МР-последовательности и клинические сведения. Отсутствие области на одном срезе не исключает опухоль. Нет внешней валидации и разбиения по пациентам.

Нормативные ссылки в исходной презентации воспроизводят материалы кейса и не являются юридической экспертизой. Поддержка сценария врача в учебном прототипе не означает готовности к клиническому использованию.
